# 功能 README：视线追踪与宠物拖动

## 视线追踪

主进程每 50 毫秒读取一次屏幕鼠标位置，并只向当前受信任的渲染页面发送相对窗口坐标。渲染进程把坐标换算为角色头部附近的归一化方向。

Spine JSON 中存在两只独立瞳孔骨骼：

- 眼_瞳孔_微动
- 眼_瞳孔L_微动

Spine Player 的 updateWorldTransform 回调位于 animationState.apply 之后。release2 在该回调中叠加平滑的小幅骨骼位移，再执行世界变换，因此不会改写 Spine 文件，也不会占用动画轨道。

不同主动画使用不同追踪强度。瞳孔最大叠加位移限制在水平 9、垂直 6 个 Spine 单位：a、b、e 中保持轻微跟随；a_win 中减弱；c、d_win 中接近静止；d 创作时暂停。关闭设置后目标位置平滑回中。

## Windows 原生整窗拖动

release2 0.2.2 不再通过 JavaScript 指针坐标和 BrowserWindow.setPosition 逐帧拖动。待办标题和宠物舞台上方分别设置 Electron 的 `-webkit-app-region: drag` 原生拖动区域，Windows 会把整个透明窗口作为同一个系统窗口表面移动。

这项修改解决多显示器、不同 DPI 或透明 GPU 分层下可能出现的宠物先移动而对话框产生拖影或看起来越来越远的问题。宠物大小和备忘框大小仍是页面内部的固定布局变量，拖动不会修改缩放值或相对间距。宠物拖动层从备忘框交互区下方开始，缩放后也不会覆盖第一条待办或“清除已完成”按钮。

输入框、按钮、待办项、设置面板和宠物悬浮工具栏使用 `no-drag` 区域，点击时不会误拖动窗口。窗口移动结束后继续沿用主进程的位置保存逻辑。

## 悬停兼容

原生拖动区域不会承担页面点击事件。主进程原有的鼠标位置采样同时用于判断鼠标是否位于宠物舞台内，因此悬停动作和操作栏仍能出现；修改宠物大小后仍可移动窗口。release2 不再动态调用 `setIgnoreMouseEvents` 关闭窗口鼠标输入，避免穿透状态与设置、待办点击失步。

## 安全边界

preload-v2.cjs 不再暴露自定义开始、移动、结束拖动消息。主进程也不再接收拖动坐标 IPC；渲染进程仍保持 contextIsolation、sandbox 和关闭 Node 集成。
