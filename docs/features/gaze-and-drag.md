# 功能 README：视线追踪与宠物拖动

## 视线追踪

主进程每 50 毫秒读取一次屏幕鼠标位置，并只向当前受信任的渲染页面发送相对窗口坐标。渲染进程把坐标换算为角色头部附近的归一化方向。

Spine JSON 中存在两只独立瞳孔骨骼：

- 眼_瞳孔_微动
- 眼_瞳孔L_微动

Spine Player 的 updateWorldTransform 回调位于 animationState.apply 之后。release2 在该回调中叠加平滑的小幅骨骼位移，再执行世界变换，因此不会改写 Spine 文件，也不会占用动画轨道。

不同主动画使用不同追踪强度。release2 将瞳孔最大叠加位移限制在水平 9、垂直 6 个 Spine 单位：a、b、e 中保持轻微跟随；a_win 中减弱；c、d_win 中接近静止；d 创作时暂停。关闭设置后目标位置平滑回中。

## 直接拖动宠物

宠物舞台监听主鼠标指针：

1. 按下时由主进程直接读取 Windows 的绝对鼠标坐标，并记录窗口起点。
2. 渲染进程不再传递 screenX 或 screenY，只用 requestAnimationFrame 把高频移动合并为每帧一次拖动通知。
3. 主进程在每次通知时重新读取系统鼠标坐标，并始终用起点计算窗口位置；窗口移动不会反过来累加到下一帧，因此不会越拖越远。
4. 松开、取消或窗口失焦时结束拖动。
5. release2 固定备忘框的布局尺寸并关闭透明窗口上的背景模糊，避免拖动时边框被拉长或留下残影。
6. 宠物与备忘框的间距只由两个缩放值计算为一次 CSS 位移；拖动窗口时两者保持同一坐标系，相对距离不变。

按钮区域不会启动拖动。窗口至少保留 80 像素在最近显示器工作区内，避免完全丢到屏幕外。窗口移动事件沿用第一版的位置保存逻辑。

## 安全边界

preload-v2.cjs 只暴露无坐标参数的开始、移动、结束拖动通知以及只读鼠标坐标事件。主进程校验消息来源，渲染进程仍保持 contextIsolation、sandbox 和关闭 Node 集成。
